# 入退室ショートカット（iPhone / Android）セットアップ手順

研究室 Wi‑Fi への接続／切断をきっかけに、端末から lab-management の入退室 API を呼び出す手順です。

- 入室報告 → `POST /start_attendance`
- 退室報告 → `POST /end_attendance`

管理者向けのサーバー起動・API キーは [vscode-extension-setup.md](./vscode-extension-setup.md) や `.env` の `API_KEY` を参照してください。

- **iPhone**: ショートカット共有リンク付きの手順（下記）
- **Android**: アプリは各自選定。退室時は `public_url` を使うヒントを記載

---

## 事前に用意するもの

| 項目 | 内容 |
|------|------|
| ユーザーID / パスワード | Web 等で登録済みのメンバー資格情報 |
| APIキー | 管理者から共有される値（サーバー `.env` の `API_KEY`） |
| サーバー接続先 | 例: `http://192.168.x.x:5000`（既定ポートは `5000`） |
| 対象 Wi‑Fi | 研究室など、入退室のトリガーに使う SSID |

## iPhone ユーザー

### 入室報告の作成

1. iPhone で **[入室報告ショートカット](https://www.icloud.com/shortcuts/10540428075d4d42ad801f0fd2274cc4)** から **「ショートカットを追加」**
2. 追加された **「入室報告」** の **「…」** を押し、詳細を開く
3. **`http://サーバーIP:ポート/start_attendance` の内容を取得** 横の **「>」** を展開し、次を設定する
   - **メソッド**: POST
   - **ヘッダ**
     - `X-Api-Key`: 管理者から受け取った APIキー
   - **リクエスト本文**（JSON）
     - `username`: 自分のユーザーID
     - `password`: 自分のパスワード  
       （テンプレートにサーバー IP・ポートが残っている場合は、自分の研究室の値に書き換える）
4. **動作確認**: 既に対象ネットワークに接続している場合、ショートカットの詳細を開き、右下の **「▶」** から実行して確認する

> ※初回実行時はプライバシー（ネットワーク等）を尋ねられます。**「常に許可」** を選択してください。

成功したら:

1. 一番上から、アイコン等を好きに決める
2. 一度戻り、下部メニューから **「オートメーション」** を選び、右上の **「+」** を押す
3. **「Wi‑Fi」** を選び、次を設定する
   - **ネットワーク**: 研究室等のよく使うネットワーク（学内 LAN）
   - **参加済み**
   - **接続が中断した後に実行**: ON
   - **すぐに実行**
4. 右上の **「次へ」** を押し、**「マイショートカット」** から先ほど設定した **「入室報告」** を選ぶ

---

### 退室報告の作成

1. iPhone で **[退室報告ショートカット](https://www.icloud.com/shortcuts/12c227c5c8124332859ccff4bb2fc1c8)** から **「ショートカットを追加」**
2. 追加された **「退室報告」** の **「…」** を押し、詳細を開く  

3. **`ファイル/end_attendance` の内容を取得** 横の **「>」** を展開し、次を設定する
   - **メソッド**: POST
   - **ヘッダ**
     - `X-Api-Key`: 管理者から受け取った APIキー
   - **リクエスト本文**（JSON）
     - `username`: 自分のユーザーID
     - `password`: 自分のパスワード
4. **動作確認**: 既に対象ネットワークに接続している場合、ショートカットの詳細を開き、右下の **「▶」** から実行して確認する

> ※初回実行時はプライバシーを尋ねられます。**「常に許可」** を選択してください。

成功したら:

1. 一番上から、アイコン等を好きに決める
2. 一度戻り、下部メニューから **「オートメーション」** を選び、右上の **「+」** を押す
3. **「Wi‑Fi」** を選び、次を設定する
   - **ネットワーク**: 研究室等のよく使うネットワーク（**入室報告と同じネットワーク**）
   - **接続解除されている**
   - **すぐに実行**
4. 右上の **「次へ」** を押し、**「マイショートカット」** から先ほど設定した **「退室報告」** を選ぶ

> **これで、研究室等のネットワークに接続されると自動で在室管理が利用できるようになりました。**

## Android ユーザー

iPhone と同様、Wi‑Fi 接続／切断をトリガーに HTTP で入退室 API を呼び出せば実現できます（Tasker / MacroDroid 等。アプリ選定は各自）。

共通のリクエスト形式:

| 項目 | 内容 |
|------|------|
| メソッド | POST |
| ヘッダ | `X-Api-Key`: 管理者から共有された APIキー<br>`Content-Type`: `application/json` |
| 本文（JSON） | `username` / `password` |

### ヒント

退室時は研究室 Wi‑Fi から切れた直後のため、**学内 LAN 上のサーバー IP（例: `http://192.168.x.x:5000`）には届きません。** 次のように分けてください。

#### 入室（Wi‑Fi 接続時）

1. **固定のサーバー IP** に対して `POST http://サーバーIP:ポート/start_attendance` を送る
2. レスポンス JSON の **`public_url`**（外部から到達可能なベース URL）を読み取る
3. その値を端末のローカル変数／ファイル等に **保存**する

成功例（抜粋）:

```json
{
  "ok": true,
  "ignored": false,
  "message": "...",
  "public_url": "https://xxxx.example.com"
}
```

#### 退室（Wi‑Fi 切断時）

1. 入室時に保存した **`public_url`** を読み出す
2. **`POST {保存した public_url}/end_attendance`** を送る  
   （例: `public_url` が `https://xxxx.example.com` なら `https://xxxx.example.com/end_attendance`）
3. ヘッダ・JSON 本文は入室時と同じ（`X-Api-Key` + `username` / `password`）

> **ポイント**: 入室は LAN 内の固定 IP、退室は入室レスポンスの `public_url`。退室ショートカットにサーバー IP を直書きしないでください。

## うまく動かないとき

| 症状 | 確認すること |
|------|----------------|
| 接続できない | 学内 LAN にいるか、`サーバーIP:ポート` が正しいか（既定は `5000`） |
| 認証エラー | `username` / `password`、および `X-Api-Key` が管理者案内と一致しているか |
| オートメーションが動かない | 対象 SSID・「参加済み」／「接続解除」の取り違え、通知の許可 |
| 手動 ▶ は成功するが自動だけ失敗 | 「すぐに実行」になっているか、低電力モード等でオートメーションが抑制されていないか |
| Android で退室だけ失敗 | 入室レスポンスの `public_url` を保存できているか、退室 URL が `{public_url}/end_attendance` になっているか（切断後はサーバー IP では届かない） |
| `public_url` が空 | サーバー側の公開トンネル設定を管理者に確認する |
